# Athena Agent OS v0.8 工程验收

## 结论边界

v0.8 的工程目标是让第三方通过签名、声明式 Capability Provider 扩展 Athena，同时保持权限、资源、审计和运行故障边界。本文只给出可在源码工作区重复验证的工程门禁；公共 Registry 运营、第三方签名密钥托管和生产 Sandbox 认证仍属于发布环境证据。

## 强制不变量

1. Provider Package 只携带声明式 JSON、Schema、Knowledge、Skill、测试、SBOM 和签名，不携带由 Runtime 直接启动的任意命令。
2. Trust Store 使用 `athena.plugin-trust.v1`，Package 与 Registry 使用 `athena.plugin.v1`，二者不能混用。
3. 实际 Grant 必须是 Provider 声明权限和资源上限的子集；网络按精确域名控制，文件、凭据、设备、World 写入和外部副作用默认拒绝。
4. 超时、并发、输入输出大小、Panic、熔断和健康检查不能影响 Runtime/Control Plane 进程存活。
5. 每次调用必须保留 Provider ID、版本、Capability、Manifest Digest、权限快照、资源快照、输入输出 Digest、Observation 和 Trace。
6. Registry 激活必须经过签名校验、扫描和人工评审；撤回、禁用和隔离立即阻止新调用。

## 验收证据

| 路线门槛 | 工程证据 |
| --- | --- |
| 示例 Provider 无需改核心 Runtime | `athena-protocol/examples/read-only-provider` 真实构建 Package 与 Trust Store；Runtime Loader 按 Registry 加载 |
| 未授权网络、凭据、设备不可访问 | `ValidateRuntimeGrant` 失败关闭测试、HTTP 精确域名限制和安全 SDK 测试 |
| Plugin 崩溃不拖垮进程 | Provider Panic 隔离、超时、熔断和审计测试 |
| 调用可追溯 | `InvocationTrace` 与 Observation Digest/Reference 测试 |

```bash
cd /Users/dom/agent-ui/agent-runtime
./scripts/run-v0.8-engineering-gates.sh
```

只有脚本输出 `ENGINEERING_VERIFIED` 才表示本地工程门禁通过。该结果不等于公共 Plugin 生态已经完成生产认证。
