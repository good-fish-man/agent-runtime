# Athena Personal Agent OS v1.0 工程验收

## 状态模型

v1.0 使用两个独立状态，禁止混写：

- `ENGINEERING_VERIFIED`：冻结协议、本地实现、单元/集成/竞态、静态检查和前端生产构建通过。
- `GA_EXTERNAL_REQUIRED`：真实十条 E2E、平台签名与公证、安全/隐私评审、恢复演练和 SLO 观测尚未全部形成发布证据。

本地脚本不能把第二个状态自动改成 GA。

## 协议与证据边界

1. `athena-protocol/compatibility/v1.0.json` 固定规范 Schema、Proto、TypeScript 产物及 Digest。
2. Golden Journey Catalog 固定十条核心用户旅程；Preflight 永远不能报告 E2E `PASS`。
3. E2E Evidence 只允许独立 Runner 使用 `X-Athena-Internal-Token` 提交到 `POST /internal/operations/golden-journeys/evidence`，请求必须包含 `owner_id` 和完整 `items`；普通管理员浏览器会话没有写入口。
4. Owner 作用域、Append-only Run、Catalog 步骤和 Evidence Kind 必须严格校验并持久化内容哈希。
5. 端到端 Provenance 不能跨无关步骤拼接。至少一个真实步骤必须同时包含 `agent_build_id`、`run_manifest_id`、`capability_id`、`action_id` 和 `observation_id`。
6. Readiness 在缺少真实设备、已验证备份、完整 E2E、平台签名或外部评审时返回 `NOT_RUN`、`EXTERNAL_REQUIRED`、`BLOCKED` 或 `FAIL`，不能乐观通过。

## 十条 Golden Journey

1. 安装并选择 Local/Remote。
2. 创建用户、模型绑定和 Agent。
3. 对话并展示任务、来源、耗时和错误。
4. 同一浏览器 Session 多步操作和人工接管。
5. 经授权的文件与应用操作。
6. 有 Claim/Evidence/Source 的研究任务。
7. 长期 Goal 的 Checkpoint、暂停、恢复和跨设备继续。
8. Memory/Experience 查看、导出和删除。
9. Candidate 评审、Build、Promotion 和 Rollback。
10. 已验证备份上的安全升级和数据保留。

## 执行

```bash
cd /Users/dom/agent-ui/agent-runtime
./scripts/run-v1.0-engineering-gates.sh
```

离线校验独立 Runner 生成的证据：

```bash
cd /Users/dom/agent-ui/athena-protocol
go run ./cmd/validate-ga-evidence -file /absolute/path/to/e2e-evidence.json
```

正式发布必须把 E2E Suite、签名制品、评审结论、恢复演练和 SLO 报告作为不可变 Release Evidence 保存。
