# Athena v0.5 工程验收

状态：**ENGINEERING_VERIFIED**

本状态表示 v0.5 Controlled Promotion 的协议、服务端治理、数据迁移、Runtime 接入、前端控制面与本地全量回归达到路线图中的工程门槛。它不关闭 v0.3 外部 Release Gate，不表示 GA，也不把声明式 Shadow 误称为线上真实模型等价验证。

## 交付范围

- 不可变 `AgentBuild`，包含 Kernel、Planner、Policy、Protocol、Skill、Strategy、Ontology、Prompt 与 Evaluation Suite 版本及 SHA-256 校验。
- 已批准 Skill/Strategy 的 Build 引用精确绑定 Candidate、Evaluation Run、Reviewer、Review Time、Version ID 与 Artifact Checksum。
- PRIVATE、同认证组织 TEAM、PUBLIC 三层 Artifact 可见性；跨组织 TEAM Build 被拒绝。
- 每次 Runtime/Agent 的流式与非流式运行都生成无密钥 `RunManifest`，记录 Build、模型配置指纹、Capability、设备、用户作用域、World Revision、Knowledge Snapshot、Budget、Feature Flag 与 Exposure。
- 模型配置指纹仅采集白名单运行字段；API key、Authorization 与知识库 Token 不进入 Manifest。
- 可选模型定价元数据结合真实 Token usage 生成服务端 Canary cost；未配置价格时不伪造金额。
- `PROPOSED -> REVIEWED -> SHADOW -> CANARY -> ACTIVE` 状态机、Revision 乐观锁与原子 Active 指针切换。
- Shadow 对生产/候选 Build 使用同一规范化输入，仅生成声明式 Route、Graph 与 Action Proposal；Side-effect Proof 强制 World Write、Network Action、Device Action、Credential Read 与 Executed Action 均为 0。
- 自动 Canary 仅允许已验证、可恢复的 R0/R1；R2/R3 自动 Canary 始终拒绝，只允许经过 Shadow 后显式激活。
- `owner_id + agent_id + promotion_id` 稳定分组；退出实验偏好跨 Promotion 延续，不会在下一轮 Canary 被静默重新加入。
- Canary 样本只能由服务端 Runtime completion path 依据不可变 Manifest 与 candidate Exposure 生成；没有公开的原始样本写接口，重复 Manifest 不能重复记样。
- Success、p95 Latency、Cost、Safety 与 Human Intervention 阈值同步聚合，命中阈值后在同一事务内暂停 Promotion。
- Rollback 仅接受 ACTIVE、CANARY 或 PAUSED Promotion，以事务切换回 Previous Build，并单独记录不可逆外部动作的 Compensation。
- 回滚后新 Task 使用 Previous Build，既有 Task、World State 与 Experience 保持可读。
- Release Control 前端提供 Build、Promotion、Shadow、Canary、Manifest、实验退出、暂停、回滚与补偿记录视图。

## 关键治理不变量

1. Build 不可原地修改；运行记录通过 Build ID 与 Checksum 复现配置边界。
2. TEAM Artifact 必须来自请求认证上下文中的同一 organization，不能由请求正文伪造。
3. Shadow 不连接设备、凭据或生产 World 写路径，失败不影响用户任务。
4. R2/R3 自动 Canary 数量必须为 0。
5. Canary 指标由 Runtime 结束路径生成，客户端不能提交任意成功率或安全分。
6. 用户退出实验后，新 Promotion 默认仍为 CONTROL。
7. 回滚只切换版本指针；不会删除历史 Build、Manifest、Task、World 或 Experience，也不会假装撤销不可逆副作用。

## 自动验收

在工作区执行：

    ./agent-runtime/scripts/run-v0.5-engineering-gates.sh

门禁覆盖：

- athena-protocol：Deployment contract、全量 schema/fixture/freeze check、`go vet ./...`。
- agent-runtime-client：Deployment/Runtime/Migration 专项测试、`go test ./...`、`go vet ./...`。
- agent-runtime：`go test ./...`、`go vet ./...`。
- athena-launcher：`go test ./...`、`go vet ./...`。
- frontend/agent-ui：`npm run lint`、`npm run build`。

Runtime 与 Launcher 的 httptest 需要本机 loopback；受限沙箱中的 `bind: operation not permitted` 是测试环境限制。本次最终门禁已在允许 loopback 的环境复跑并完整通过。

## 专项证据

- 同组织 TEAM Skill 可进入 Build，其他组织请求被拒绝。
- RunManifest 对 API key、Authorization 与知识 Token 保持无感；模型定价元数据进入指纹并可计算 Canary cost。
- Effectful Shadow Evaluator 被拒绝且不写入 Shadow Result。
- 同一 Manifest 第二次上报 Runtime outcome 被唯一约束拒绝。
- R2 Build 不能进入 CANARY，但可在显式确认与已通过 Shadow 后激活。
- Canary 达到最小样本后命中阈值会同步返回 PAUSED，远低于一分钟停止门槛。
- 用户退出实验后，下一 Promotion 的 Exposure 仍为 opted-out CONTROL。
- PROPOSED Promotion 不能调用 Rollback。
- 原子 Rollback 后，新 Manifest 绑定 Previous Build；预置 Task、World State 与 Experience 仍各保留一条。
- 从旧数据库执行幂等迁移后，九张 v0.5 Deployment 表全部存在且既有用户、会话与记忆未丢失。

## 边界说明

- 默认 Shadow Evaluator 是服务端纯声明式、PLAN_ONLY 评估器，用于验证发布物差异、预算、风险和零副作用边界；它不会调用线上模型，因此不证明候选 Prompt 在真实模型上的语义输出完全等价。真实行为质量仍由 v0.4 Offline Evaluation、后续受控 Canary 和人工审批共同约束。
- 未配置模型价格时 Cost 为 0，系统不会猜测供应商价格；运营方应给需要成本熔断的模型提供每百万 Token 微货币费率。
- 前端生产构建通过，但 Vite 报告主 JavaScript chunk 超过 500 kB；这是后续性能优化项，不阻断本版本治理验收。

## 未关闭的发布前置条件

v0.3 的三平台签名安装、完整 500 Journey Soak、完整十 Span Trace 与生产近似终态 Experience 覆盖率仍需外部证据。缺少这些证据时，可以继续开发 v0.6/v0.7，但不得声明 v0.3-v0.5 GA。
