# Athena v0.2 跨仓库兼容矩阵

[English](./v0.2-compatibility-matrix.md)

本文档是 `architecture/agent-os-v0.2` 开发线的跨仓库正式契约。组装 Release 时必须遵守：不在本矩阵中的组件，不得放入 `v0.2.0` Manifest。

## 组件矩阵

| 组件 | 开发分支 | 发布版本 | 必需依赖 | 职责 |
| --- | --- | --- | --- | --- |
| `athena-protocol` | `architecture/agent-os-v0.2` | `v0.2.0` | Go 1.25 | Protocol v4 的 Go/TypeScript 类型、JSON Schema、Protobuf Schema 与 Golden Fixtures |
| `agent-runtime` | `architecture/agent-os-v0.2` | `v0.2.0` | `athena-protocol v0.2.0`、`logx v0.2.0` | 意图、路由、规划、模型循环及收到 Observation 后继续执行 |
| `agent-runtime-client` | `architecture/agent-os-v0.2` | `v0.2.0` | `agent-runtime v0.2.0`、`athena-protocol v0.2.0`、`logx v0.2.0` | 持久化控制面、策略、审批、设备路由、World State、事件与 Outbox |
| `athena-launcher` | `architecture/agent-os-v0.2` | `v0.2.0` | `athena-protocol v0.2.0`、`logx v0.2.0` | Device Runtime、幂等执行、重连重放、浏览器/桌面能力与安装包 |
| `athena-agent-ui` | `architecture/agent-os-v0.2` | `v0.2.0` | 自动生成的 Protocol v4 TypeScript 契约 | Task Timeline、审批、取消、事件恢复及错误/证据展示 |
| `logx` | `architecture/agent-os-v0.2` | `v0.2.0` | 无 Athena 依赖 | 统一关联 Span、耗时、调用方定位及结构化错误链 API |

`logx v0.2.0` 新增所有 v0.2 服务使用的公共 `StartSpan` API，因此远程构建其他服务前必须先发布它。

## 传输协议兼容性

| 契约 | v0.2 值 | 兼容规则 |
| --- | --- | --- |
| 协议标识 | `athena.agent.v4` | 设备 Action、Progress、Observation、Cancel 必须使用该标识 |
| 设备通道 | 配置 Public Prefix 下的 WebSocket `/v1/control/device` | Launcher 主动连接；Frontend 不参与设备传输 |
| Task 事件 | SSE `/v1/control/tasks/:task_id/events/stream` | 每个 Task 的 Sequence 单调递增；客户端按最后 Sequence 恢复 |
| 审批 | `GET /v1/control/approvals`、`POST /v1/control/approvals/:approval_id/decision` | 使用 Revision/CAS；只有 `ALLOW` Action 可以发送到设备 |
| Task 取消 | `POST /v1/control/tasks/:task_id/cancel` | 取消结果持久化；设备在线时向当前 Action 传播取消 |
| 未知 JSON 字段 | 兼容 Reader 忽略 | Writer 不得依赖未知字段改变 v0.2 行为 |
| Protobuf/JSON Fixture | `athena-protocol/testdata/v4` | 所有 Go 与 TypeScript 适配器必须通过 Golden Fixture 校验 |

## 数据兼容性

`agent-runtime-client` 是 Task 与 World Model 状态的唯一持久化所有者。启动迁移会创建 `os_*` Schema；当 v0.2 新表不存在时，将旧 `os_step`/`os_event` 重命名为正式表名。

v0.2 必需表：

```text
os_task                  os_task_step             os_task_event
os_action                os_observation           os_artifact
os_approval              os_outbox                os_world_state
os_world_entity          os_world_relation        os_world_evidence_ref
os_device                os_device_capability     os_capability_definition
os_capability_instance
```

旧 `agent_control_*` 数据使用稳定 ID 进行一次性迁移，不删除现有业务数据。生产升级前必须备份数据库，并在副本上预演迁移。

## 发布顺序

Go Module 在远程 CI 中依赖已发布 Tag，因此顺序必须固定：

1. 发布并标记 `logx v0.2.0`。
2. 发布并标记 `athena-protocol v0.2.0`。
3. 发布并标记 `agent-runtime v0.2.0`。
4. 发布并标记 `agent-runtime-client v0.2.0`。
5. 构建并发布 `athena-agent-ui v0.2.0`。
6. 最后发布 `athena-launcher v0.2.0`，Manifest 必须引用上述确定产物及其 SHA-256。

所有引用产物存在之前，不得发布 Launcher Manifest。禁止在同一 Tag 下替换资产，否则已记录的 SHA-256 会失效。

## 发布门禁

本地单元测试是必要条件，但不能单独证明正式版已经达到 GA。最终 `v0.2.0` Tag 前必须记录：

- Protocol/Golden 测试与所有仓库测试结果。
- 数据库升级预演以及备份/恢复预演。
- macOS、Windows、Linux 安装包冒烟测试。
- 分版本落地计划中的 7 个 v0.2 验收场景。
- 核心 E2E 连续 500 次、非环境原因成功率至少 98%。
- 不可逆操作重复副作用为 0。
- 必需 Span 覆盖率 100%。
- 对日志、Task Event、Observation 与 Artifact 的凭据泄漏扫描。

在上述外部门禁记录完成前，本分支产物属于 `v0.2.0` Release Candidate，而不是已经验证的 GA 正式版。
