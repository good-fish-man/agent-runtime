# Athena v0.4 工程验收

状态：**ENGINEERING_VERIFIED**

本状态只表示 v0.4 Candidate Learning 的代码、数据模型、协议、前端和本地工程回归达到计划内门槛。它不表示 v0.4 可以绕过 v0.3 的外部 Release Gate 发布，也不表示 GA。

## 交付范围

- athena.learning.v2 声明式 Skill、Strategy、Candidate 与 Demonstration 契约。
- Candidate 从多个独立、脱敏 Experience 聚类，强制包含成功样本与同模式失败反例。
- Capability 注册、Operation 白名单、风险上限、直接代码执行器拒绝和 Prompt Injection 隔离。
- 冻结 Fixture 上的离线结构化 Replay、Baseline 对比、最小样本、Wilson 置信区间和安全分。
- Candidate 编辑后旧 Evaluation 立即失效；重新评测后才可进入人工 Review。
- Approve/Reject 的 Reviewer、Review Note、时间、Revision 与不可变 Skill/Strategy Version。
- PRIVATE、基于认证用户 organization_id 的 TEAM、以及 PUBLIC 可见性。
- 显式演示记录、敏感输入暂停、语义步骤预览/编辑/确认、确认来源和幂等重试。
- 只有已确认、无敏感暂停、无脱敏占位、学习开关开启且具有明确站点范围的演示，才会生成私有 Experience；原始 Action 参数不会进入学习 payload。
- Candidate Inbox、Evidence、Evaluation、Diff、编辑、重新评测、Review 与可见性控制。

## 关键安全不变量

1. Candidate 不能注册 Capability、扩大 Credential Scope、降低 Capability 风险或引用直接代码执行器。
2. Evaluation 只能使用本地 mock/simulation；不能连接 Launcher、真实浏览器、网络、凭据或生产账号。
3. APPROVED_FOR_USE 不自动替换 Agent 默认行为，也不等于生产 Promotion。
4. TEAM 数据只对同一认证组织可见；请求不能伪造组织 ID。
5. 不同用户不能用相同 Skill/Strategy ID 覆盖他人的物化版本。
6. 未确认、已丢弃、敏感暂停或学习关闭时的演示不会进入 Candidate 证据池。
7. athena.learning.v1 保持冻结；强化后的契约使用 athena.learning.v2，不通过修改指纹掩盖破坏性变更。

## 自动验收

在工作区执行：

    ./agent-runtime/scripts/run-v0.4-engineering-gates.sh

门禁覆盖：

- athena-protocol: make check、go vet ./...
- agent-runtime-client: go test ./...、go vet ./...
- agent-runtime: go test ./...、go vet ./...
- athena-launcher: go test ./...、go vet ./...
- frontend/agent-ui: npm run lint、npm run build

Runtime 与 Launcher 的部分测试使用 httptest 本机端口；受限沙箱会禁止监听并产生环境性 panic，应在 CI 或允许 loopback 的本机测试环境运行，不能将该限制误判为产品失败。

## 专项证据

- 真实 SQLite 流程：Experience -> Fixture -> Suite -> Candidate Replay -> Review -> 不可变 Skill Version。
- 真实 SQLite 演示流程：Task/Action -> Record -> Preview -> Confirm -> Sanitized Experience。
- 演示确认重试只产生一条 Experience；数据库 payload 不包含原始密码参数。
- 敏感演示可保留确认审计，但不会生成学习 Experience。
- Candidate 必须具有至少两条成功 Experience、一条同 Action Pattern 失败反例、总计至少四条独立 Experience，并跨至少两个环境/站点上下文。
- 修改 Candidate 后不能复用旧 Evaluation；未重新评测不能批准。
- TEAM Skill 在同组织可见，在其他组织和无组织上下文不可见。
- 跨用户同 Artifact ID 物化被拒绝，原 Owner 的 latest version 和版本数量保持不变。

## 未关闭的发布前置条件

权威路线仍要求先关闭 v0.3 外部证据，包括三平台签名安装器、完整打包 500 Journey Soak、完整十 Span 验收 Trace，以及生产近似终态 Task 的 Experience 覆盖率。缺少这些证据时：

- 可以继续开发和回归 v0.4 后续版本；
- 不得声明 v0.3/v0.4 GA；
- 不得冻结仍处于验证期的存储字段、RPC 或事件协议；
- 不得让 Candidate 自动影响生产规划或执行。
