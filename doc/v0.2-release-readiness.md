# Athena v0.2 Release Readiness

[Simplified Chinese](./v0.2-release-readiness.zh-CN.md)

This report separates implementation completion from General Availability evidence. The `architecture/agent-os-v0.2` branch is a release-candidate line until every external gate below is recorded.

## Implemented Baseline

| Area | Status | Evidence |
| --- | --- | --- |
| Canonical Protocol v4 | Implemented | `athena-protocol` owns Go, TypeScript, JSON Schema, Protobuf, and golden fixtures for `athena.agent.v4` |
| Trace propagation | Implemented | `trace_id` travels through Action, Progress, Observation, Cancel, durable Action/Observation rows, Task Events, and Launcher spans |
| Durable Control Plane | Implemented | Tasks, Steps, Actions, Observations, Artifacts, Approvals, World State, Events, and Outbox use the `os_*` schema |
| Device control channel | Implemented | Launcher maintains the WebSocket connection, capability instances, heartbeat/reconnect, idempotent journal, cancel, and replay |
| Approval boundary | Implemented | `ASK_USER` is durable, owner-scoped, revision-checked, and cannot reach a device before approval |
| Observation continuation | Implemented | Runtime Client returns real device Observation data to the Runtime model loop for bounded continuation and verification |
| Frontend task experience | Implemented | Timeline restore, SSE resume, Approval decisions, Task cancel, evidence/error rendering, and running-state recovery |
| Sensitive-data persistence boundary | Implemented | Attachment bytes are transient; credential-like fields, URLs, errors, evidence, and World Patches are scrubbed before persistence |

## Required Span Map

| Span | Owner | Boundary |
| --- | --- | --- |
| `intent.parse` | Agent Runtime | Natural-language request to structured Intent |
| `route.plan` | Agent Runtime | Intent to primary route, capabilities, and fallbacks |
| `world.query` | Runtime Client | Durable World State lookup |
| `model.invoke` | Agent Runtime | Streaming and non-streaming model invocation, token usage, and finish reason |
| `action.policy` | Runtime Client | Policy/risk validation before persistence or dispatch |
| `action.dispatch` | Runtime Client | Idempotency, device routing, durable dispatch, and Observation wait |
| `device.execute` | Launcher | Actual device-side execution and durable journal outcome |
| `perception.observe` | Launcher | Browser execution plus the resulting bounded page observation |
| `world.apply` | Runtime Client | Observation/evidence persistence and World Patch projection |
| `task.verify` | Runtime Client | Observation correlation and Task state transition |

Every terminal span records a Trace ID, span ID, UTC finish time, `cost_ms`, `cost_us`, outcome fields, and one formatted error chain on failure. Verify a real E2E trace with:

```bash
./scripts/verify-v0.2-spans.sh ~/.athena/logs
# Or require one specific trace:
./scripts/verify-v0.2-spans.sh ~/.athena/logs arc-your-trace-id
```

The verifier requires all ten terminal spans to belong to the same Trace ID; unrelated or stale partial traces cannot satisfy the gate.

## Local Verification

The following checks are required before every release candidate:

```bash
cd athena-protocol && make check
cd logx && go test ./...
cd agent-runtime && go test ./...
cd agent-runtime-client && go test ./...
cd athena-launcher && go test ./...
cd frontend/agent-ui && npm run protocol:check && npm run lint && npm run build
```

The repository suites cover protocol fixtures, state transitions, idempotency, duplicate observations, approval decisions, cancellation, recovered observations, journal recovery, stable browser Target IDs, tab reconciliation, and credential scrubbing. A passing local suite is necessary but is not equivalent to cross-platform GA evidence.

## Release Decision

The branch is suitable for `v0.2.0-rc` builds after all local checks pass. It must not be described as verified `v0.2.0` GA until every external gate is complete. Release ordering is defined in the [compatibility matrix](./v0.2-compatibility-matrix.md).
