# Athena v0.2 Compatibility Matrix

[Simplified Chinese](./v0.2-compatibility-matrix.zh-CN.md)

This document is the cross-repository contract for the `architecture/agent-os-v0.2` line. It is normative for release assembly: a component outside this matrix must not be placed in a `v0.2.0` manifest.

## Component Matrix

| Component | Source line | Release version | Required dependencies | Responsibility |
| --- | --- | --- | --- | --- |
| `athena-protocol` | `architecture/agent-os-v0.2` | `v0.2.0` | Go 1.25 | Canonical Protocol v4 Go/TypeScript types, JSON Schema, Protobuf schema, and golden fixtures |
| `agent-runtime` | `architecture/agent-os-v0.2` | `v0.2.0` | `athena-protocol v0.2.0`, `logx v0.2.0` | Intent, routing, planning, model loop, and Observation-driven continuation |
| `agent-runtime-client` | `architecture/agent-os-v0.2` | `v0.2.0` | `agent-runtime v0.2.0`, `athena-protocol v0.2.0`, `logx v0.2.0` | Durable Control Plane, policy, approvals, device routing, World State, events, and outbox |
| `athena-launcher` | `architecture/agent-os-v0.2` | `v0.2.0` | `athena-protocol v0.2.0`, `logx v0.2.0` | Device Runtime, idempotent execution, reconnect/replay, browser/desktop capabilities, packaging |
| `athena-agent-ui` | `architecture/agent-os-v0.2` | `v0.2.0` | generated Protocol v4 TypeScript contract | Task Timeline, Approval decisions, cancel, event restore, and error/evidence rendering |
| `logx` | `architecture/agent-os-v0.2` | `v0.2.0` | none from Athena | Correlated spans, timing, caller attribution, and structured error-chain API |

`logx v0.2.0` adds the public `StartSpan` API used by all v0.2 services, so it must be published before those services are built remotely.

## Wire Compatibility

| Contract | v0.2 value | Compatibility rule |
| --- | --- | --- |
| Protocol identifier | `athena.agent.v4` | Device Actions, Progress, Observations, and Cancels must use this exact identifier |
| Device transport | WebSocket `/v1/control/device` under the configured public prefix | Launcher connects proactively; the Frontend is not part of the device transport |
| Task events | SSE `/v1/control/tasks/:task_id/events/stream` | Event sequence is monotonic per Task; clients resume with the last observed sequence |
| Approvals | `GET /v1/control/approvals`, `POST /v1/control/approvals/:approval_id/decision` | Decisions use revision/CAS; only `ALLOW` Actions may reach a device |
| Task cancellation | `POST /v1/control/tasks/:task_id/cancel` | Cancellation is durable and propagated to the active device Action when connected |
| Unknown JSON fields | ignored by compatible readers | Writers must not rely on an unknown field changing v0.2 behavior |
| Protobuf/JSON fixtures | `athena-protocol/testdata/v4` | All Go and TypeScript adapters must pass the golden fixture checks |

## Persistence Compatibility

`agent-runtime-client` owns all durable Task and World Model state. Startup migration creates the `os_*` schema and renames legacy `os_step`/`os_event` tables when the v0.2 names do not yet exist.

Required v0.2 tables:

```text
os_task                  os_task_step             os_task_event
os_action                os_observation           os_artifact
os_approval              os_outbox                os_world_state
os_world_entity          os_world_relation        os_world_evidence_ref
os_device                os_device_capability     os_capability_definition
os_capability_instance
```

Legacy `agent_control_*` records are migrated once with stable identifiers. Existing application data is not deleted. Before a production upgrade, back up the database and rehearse the migration against a copy.

## Release Order

The order is mandatory because Go modules are resolved from published tags in repository CI:

1. Publish and tag `logx v0.2.0`.
2. Publish and tag `athena-protocol v0.2.0`.
3. Publish and tag `agent-runtime v0.2.0`.
4. Publish and tag `agent-runtime-client v0.2.0`.
5. Build and publish `athena-agent-ui v0.2.0`.
6. Publish `athena-launcher v0.2.0` last, with a manifest containing the exact service/UI artifacts and SHA-256 values.

Do not publish the Launcher manifest before every referenced artifact exists. Replacing an asset under an existing tag invalidates its recorded SHA-256 and is not supported.

## Release Gate

Local unit tests are necessary but do not by themselves declare General Availability. Before the final `v0.2.0` tag, record evidence for:

- Protocol/golden tests and all repository test suites.
- Database upgrade rehearsal and backup/restore rehearsal.
- macOS, Windows, and Linux package smoke tests.
- The seven v0.2 acceptance scenarios from the versioned delivery plan.
- 500 core end-to-end runs with at least 98% non-environmental success.
- Zero duplicate irreversible side effects.
- Complete required-span coverage.
- A credential-leak scan of logs, Task Events, Observations, and artifacts.

Until those external gates are recorded, builds from this branch are `v0.2.0` release candidates, not verified GA releases.
