# Athena Agent OS v0.9 工程验收

## 结论边界

v0.9 将系统收敛到可进行正式发布验证的生产工程基线。源码和本地测试可以验证加密、完整性、租约、背压、回滚与可观测性，但不能替代平台证书、公证、渗透测试、真实灾难恢复和 24/72 小时 SLO 观测。

## 工程门禁

### 供应链与升级

- Release Manifest、组件 SHA-256、Ed25519 签名、SBOM 和平台签名状态均进入发布契约。
- 下载、解包和激活前验证大小、Digest、签名和目标平台。
- 更新前创建恢复点；激活失败使用保留版本回滚。

### 数据恢复

- Runtime Client 逻辑备份使用分块 AES-GCM，Manifest 使用独立 HMAC。
- `Verify` 必须解密认证全部制品，并将 `VERIFIED` 状态重新签名后持久化。
- 备份列表重新校验 Manifest 和制品 SHA/大小；仅 `VERIFIED` 备份关闭 Control Plane 恢复门禁。
- Launcher 托管 PostgreSQL 恢复点只有在身份、HMAC、状态、制品 SHA 和大小均通过时才进入 Readiness `PASS`；仅存在文件名或 `manifest.json` 不构成证据。
- Restore 在认证、确认字符串和目标校验完成前不得调用数据库恢复器。

### 高可用与 SLO

- Device 使用数据库租约和 fencing token；过期所有者不能提交 Observation。
- Runtime 有最大并发、最大队列、排队超时、请求 Deadline、熔断和优雅排空。
- Health/SLO 不输出凭据、数据库密码、Cookie、截图或模型私有内容。

## 执行

```bash
cd /Users/dom/agent-ui/agent-runtime
./scripts/run-v0.9-engineering-gates.sh
```

脚本通过只产生 `ENGINEERING_VERIFIED`。以下发布门禁仍必须在目标环境完成：无 P0/P1 的安全评审、真实 DR 演练、macOS/Windows/Linux 签名安装与升级、故障注入、并发压测、24/72 小时稳定性和 SLO 报告。
