# Athena v0.7 工程验收

状态：**ENGINEERING_VERIFIED**

本状态表示 v0.7 Persistent Goal、受限多 Agent 协作、统一调度、Checkpoint 和跨设备恢复的协议、服务端、数据库、前端与自动回归达到路线图中的工程门槛。它不关闭 v0.3 外部 Release Gate，也不表示生产 GA。

## 交付范围

- `Goal`、`TaskGraph`、`Checkpoint`、`SpecialistResult` 和 `ExecutionBudget` 使用统一的 `athena.orchestration.v2` 契约；已发布的 v1 保持冻结。Goal 支持 `WAITING_USER`、`WAITING_DEVICE`、暂停、恢复、取消和终态。
- `POST /goals/planned` 在一个数据库事务中原子创建 Goal、有限 Task Graph 与首个 Checkpoint，不再由前端通过多次请求拼装。
- Task 使用稳定 `task_key` 与全局唯一 `task_id`；依赖图拒绝环、缺失依赖、超深图和无界任务数。
- Supervisor 只调度有限的 Research、Browser、Desktop、File 和 Synthesis Specialist；并发、深度、Token、时间、查询、页面和 Action 均有硬上限。
- Device Task 仅在收到成功的真实 Observation 后允许完成；没有 Observation 的“成功”会被改写为失败，失败结果不能满足成功条件。
- Task 与设备解耦，Action 才绑定设备；首选设备离线时进入 `WAITING_DEVICE`，设备恢复或改路由后从 Checkpoint 继续。
- World Slice 只暴露 Task 声明的 key；嵌套密码、Secret、Token、Cookie、Credential、Authorization 和 API Key 被递归移除，集合、深度和字符串长度均受限。
- 每个 SpecialistResult 都绑定 Producer、Trace、Capability、Runtime RunManifest、AgentBuild 和模型配置指纹；外部效果同时保留 Observation 引用。
- Checkpoint 使用父哈希形成可验证链；损坏或断裂的链不能恢复。已确认 Action 的幂等键进入 Checkpoint，重启后不会重复副作用。
- Pause 会取消正在运行的上下文；Resume 从最新有效 Checkpoint 新建受限运行，不复用已取消上下文。
- Scheduled Task 与交互 Goal 共用同一个 Control Plane、Task 协议和审计路径；Scanner 由 App 生命周期管理，启动失败或关闭时不会泄漏后台循环。
- 前端 Goal Inbox 展示触发来源、设备路由、执行次数、Provenance、Evidence/Observation/Effect、Checkpoint 哈希和预算，并要求 `WAITING_USER` 提交明确回答后才能恢复。
- 数据库迁移初始化 Goal、Task、Checkpoint、Result 和 Schedule Slot 五组持久化结构；升级可重复执行，另提供显式破坏性回滚脚本。

## 路线图场景验收

1. **五天旅行计划**：Research 发现地点/偏好缺口后进入 `WAITING_USER`；用户回答后继续 Synthesis，结果保留来源与 Provenance。
2. **关闭后恢复**：Supervisor 在 Checkpoint 后重建，恢复时跳过已经确认的 Action idempotency key，不重复外部效果。
3. **受限上下文共享**：Research 和 Browser 只收到各自声明的 World Slice；嵌套敏感字段和其他设备状态不会泄漏。
4. **预算停止**：Token、时间、查询、页面或 Action 任一预算耗尽都会停止继续调度并进入明确等待/失败状态，不会无限搜索。
5. **跨设备接管**：首选设备离线后等待；另一设备上线并产生 Action/Observation 后完成，Checkpoint 只记录新设备作用域，不混入原设备页面状态。

## 关键治理不变量

1. Supervisor 不能递归创建长期 Goal、隐藏 Sub-Agent、生成代码直接执行或无限扩张任务图。
2. Browser、Desktop、File 类型 Task 必须声明 `requires_device=true`；模型输出不能绕过 Device Control Plane。
3. 用户接口只能访问自己的 Goal；内部 Task 启动、结果写入和手工 Checkpoint 写入要求严格匹配的内部服务令牌。
4. 没有成功 Observation 的设备动作不能被记录为成功，也不能满足 Outcome success criterion。
5. Checkpoint 中的外部效果必须引用 Observation；损坏的哈希链、未来 Revision 或不一致 Goal/Run 绑定拒绝恢复。
6. Scheduled Task 不拥有第二套执行器；它只能把标准 Task 送入同一 Supervisor。
7. Device-scoped World State 不跨设备复制；跨设备只共享经过声明、裁剪和审计的结果。

## 边界说明

- 多日任务与跨设备场景由确定性 Runtime/Device Fixture 加速验证；尚未替代真实多日 Soak、真实断网/断电和多台签名客户端测试。
- 当前是单 Control Plane 实例的持久化调度，不是高可用分布式 Scheduler；HA、租约和故障转移属于 v0.9。
- Inbox 的快速创建仅提供有界 Research → Synthesis 模板；复杂 Goal 应由 Chat Planner 生成，不让 UI 自行拼接任意 Task Graph。
- 前端生产构建通过，但 Vite 仍报告主 JavaScript chunk 偏大；该性能项不阻断 v0.7 治理验收。

## 未关闭的发布前置条件

v0.3 的三平台签名安装、完整 500 Journey Soak、完整十 Span Trace 和生产近似终态 Experience 覆盖率仍需外部证据。缺少这些证据时，可以继续后续工程开发，但不得声明 v0.3-v0.7 GA，也不得冻结仍处于验证期的存储字段、RPC 或事件协议。
