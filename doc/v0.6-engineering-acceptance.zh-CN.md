# Athena v0.6 工程验收

状态：**ENGINEERING_VERIFIED**

本状态表示 v0.6 Evidence Knowledge 与 Controlled Ontology 的协议、服务端治理、数据库迁移、Runtime 注入、前端证据面板和全工作区回归达到路线图中的工程门槛。它不关闭 v0.3 外部 Release Gate，不表示 GA。

## 交付范围

- `Claim`、`Evidence`、`Contradiction`、`Snapshot`、Ontology Pack/Version/Candidate/Migration 协议及 JSON Schema。
- Claim 必须引用持久化、可访问且不跨越 Owner/Organization/Scope 的 Evidence；单个页面 Observation 不能直接成为 Knowledge。
- Research 结果只写入不可变 Evidence，不自动创建 Claim；相同内容在后续 Task 中重新观察时生成新的 Evidence，保留独立时效和 Provenance。
- OFFICIAL、RESEARCH、PAGE_OBSERVATION、USER_CONFIRMATION 使用服务端信任等级与 Freshness Policy，客户端不能自报权威等级。
- 时间敏感 Claim 必须有服务端约束的有效期；过期或全部证据陈旧时不作为确定事实返回。
- 同 Subject/Predicate、重叠时间范围但值不同的 Claim 生成 Contradiction，不静默覆盖。
- KEEP_CLAIM、MARK_UNCERTAIN、RETRACT_ALL 裁决带 Reviewer、时间和说明；保留其他未解决冲突，已解决冲突不会继续污染获胜 Claim。
- Hybrid Retrieval 组合结构化过滤、关键词、确定性本地向量、受限关系遍历、时间过滤和证据排序，并强制 Result、Token、Time、Sensitivity 与 Relation Depth 预算。
- USER、认证组织 ORGANIZATION、PUBLIC 检索边界由服务端认证上下文决定；请求正文中的 `organization_ids` 会被覆盖，不能伪造组织权限。
- Runtime 将 Claim ID、Determination、关键 Evidence URL、权威度、时效和 Contradiction 注入受限上下文，并把 Knowledge Snapshot 校验和绑定到不可变 RunManifest。
- Snapshot 对规范化 Query、Claim/Evidence 内容摘要、Determination、冲突和 Ontology 版本计算校验和；同一 Snapshot 不能绑定不同 RunManifest。
- Belief 仅由检索结果派生；Prediction Error 只产生 Experience 信号，不能修改 Policy。
- Ontology Candidate 只能运行 OFFLINE Evaluation，必须人工 Review；生产 Migration 必须再次人工审批，并由受限声明式迁移器执行。
- Ontology Pack 的 Active Version 与 Migration Receipt 在事务中切换，版本漂移或并发 Revision 冲突会拒绝执行。
- 前端 Evidence Knowledge 面板显示 Claim 状态、来源链接、Trust/Freshness、冲突裁决、Snapshot/Manifest 和当前 Ontology Pack。

## 关键治理不变量

1. Observation 和 Research Source 是证据，不是真相；没有证据处理就不能成为 Claim。
2. 所有可作为确定事实返回的 Claim 至少有一个当前请求可访问的 Evidence。
3. 过期、证据全部陈旧、已撤回或存在冲突的 Claim 不能标记为 `FACT`。
4. 用户确认不能直接提升为 PUBLIC Knowledge。
5. Organization 可见性只来自已认证用户所属组织，客户端字段不参与授权。
6. 冲突裁决是审计事件，不删除历史 Claim/Evidence；获胜 Claim 只清除本次已解决的冲突引用。
7. Ontology Candidate、Review、Migration Review 和 Tool Execution 是不同阶段，任何一步都不能自动跳过。

## 专项证据

- 单个 PAGE_OBSERVATION 创建 Claim 被拒绝；Research Capture 后 Claim 数量仍为 0。
- 相同网页内容在两个不同 Task 中形成两个独立 Evidence 与 SourceTaskID。
- 伪造请求体 `organization_ids` 无效；同认证组织可检索，其他组织返回 0 条。
- 过期 Claim 默认不返回；显式历史检索也不会把它标记为确定事实。
- PUBLIC Claim 的私有冲突细节不会泄露给公共读取者。
- 冲突 KEEP_CLAIM 后，获胜 Claim 恢复为 `FACT`，本次冲突引用被清除，裁决人和说明保留。
- Ontology 未审批 Migration 无法执行；审批后受限迁移器生成 Receipt 并原子推进版本。
- 从旧数据库执行幂等升级后，八张 v0.6 Knowledge/Ontology 表全部存在，既有用户、会话与记忆保持不变。
- Knowledge Snapshot 成功绑定到对应 RunManifest，校验和进入运行复现边界。

## 边界说明

- 当前默认向量器是本地确定性哈希向量，用于可重放的混合召回，不等同于生产级多语言语义 Embedding；可通过受控 `Embedder` 注入替换。
- 用户端 Claim 创建接口仅允许 USER scope。ORGANIZATION/PUBLIC 发布目前保留给受信任的内部发布流程，尚未提供普通用户自助发布入口，避免个人偏好被错误扩大作用域。
- 当前本体迁移器只执行受限声明式操作，不运行生成代码，也不修改 Auth、Policy、Credential 或 Sandbox。
- 前端生产构建通过，但 Vite 仍报告主 JavaScript chunk 超过 500 kB；该性能项不阻断本版本治理验收。

## 未关闭的发布前置条件

v0.3 的三平台签名安装、完整 500 Journey Soak、完整十 Span Trace 与生产近似终态 Experience 覆盖率仍需外部证据。缺少这些证据时，可以继续开发 v0.7，但不得声明 v0.3-v0.6 GA。
